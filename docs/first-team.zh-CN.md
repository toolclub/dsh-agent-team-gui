# 跑通你的第一个多模型小队

[English](first-team.md) · [返回中文 README](../README-zh.md)

本指南从一份可导入的配方开始：让规划成员写验收标准、实现成员交付一个待办清单、审核成员
检查代码和测试证据。完成后，你会有一支可复用的小队、一个本地演示项目，以及可以展开查看
成员输出和 Token 用量的运行记录。

这是供你在自己的模型配置上复现的任务；目前未附真实模型完成此任务的实测结果，不承诺固定
耗时、成功率或节省比例。README 中的截图使用预置示例数据，不是这个任务的运行证据。

## 1. 安装并确认入口

需要已安装的 DeepSeek Harness（DSH）`>=0.1.5-rc.1 <0.1.6-0`、Web profile、pnpm，以及
Node.js `>=22.19.0 <23` 或 `>=24.0.0`。Node.js 23 不在支持范围内。
仓库 CI 当前使用 DSH `0.1.5-rc.1`；这与声明兼容范围是两回事。

```sh
node --version
pnpm --version
dsh --version
dsh plugin --profile web add -w https://github.com/toolclub/dsh-agent-team-gui/releases/download/v1.1.1/dsh-agent-team-gui-1.1.1.tgz
dsh --profile web
```

如果 Web 已经运行，安装完成后重启 DSH 进程并刷新页面。进入 **Settings → 小队**，
应能看到**小队、成员库、配方与数据**三个页签。预编译包已包含运行代码，无需授权插件的
Git `prepare` 构建。

在 DSH 设置中先配置至少一条可用的提供方/模型路由，并在普通单人对话中确认该模型可用。
每个成员可以选择不同模型，也可以先全部复用同一条路由。配方不会提供 API Key，也不会帮你
创建模型账号；凭证继续由 DSH 管理。当前对话的模型还会负责动态规划，因此也必须可用。

## 2. 导入配方并映射模型

打开仓库的 [Full-stack delivery 配方](../examples/full-stack-delivery.recipe.json)，使用
GitHub 的 Raw/下载入口保存 JSON 文件；也可以直接复制完整 JSON 内容。

1. 进入 **Settings → 小队 → 配方与数据**，找到**小队配方**区域。
2. 点击**选择配方文件**。读取本地 JSON 后会自动预览。若使用粘贴方式，将 JSON 放入
   **配方 JSON**文本框并点击**预览**。
3. 初次预览显示**缺少模型路由**是正常的：示例中的三名成员都使用
   `your-provider / your-model` 占位符。为每个缺失路由选择自己的**提供方**和**模型**。
4. 更改路由会自动重新预览。选择提供方时，界面会先选中其第一个模型；映射成功的缺失行会
   消失。等全部路由有效、显示**配方校验通过**后，保持**导入策略 → 创建副本**，点击
   **确认导入配方**。
5. 进入**成员库**，逐个核对新导入成员的提供方和具体模型；如需更换，选择后点击**保存**。
   这里可以为规划、实现、审核分别指定不同模型。

| 示例成员 | 首次任务中的交付 |
| --- | --- |
| Product planner | 验收标准、边界条件和交接顺序，不修改实现 |
| Implementation engineer | 文件、针对行为的测试和实际检查输出 |
| Quality reviewer | 对照验收标准独立检查，指出阻塞问题或证据支持的通过结论 |

首次使用**创建副本**会保留已有定义。如果你重复导入，可能看到带副本名称的项目，后续选择
本次导入的小队即可。**按 ID 合并**会修改同 ID 的定义；已有共享成员时应先查看受影响小队。

配方导入使用本地文件或粘贴的 JSON；当前版本不从配方 URL 拉取内容。导入预览不会启动
小队成员。小队编辑器中的**试运行计划**是另一项功能，会调用规划模型并计入 Token。

## 3. 调整首次体验策略

在**小队**页签选中刚导入的 `Full-stack delivery` 小队，展开**编排策略**，设置：

| 设置 | 首次体验值 | 原因 |
| --- | --- | --- |
| 小队使用方式 | Host 强制派工 | 首跑明确触发小队 |
| 派工策略 | 执行已派任务 | 示例默认智能策略可能跳过简单任务 |
| 成员选择 | 全部成员 | 示例默认“按任务选择”，首次便于观察三个角色 |
| 固定顺序 | 关闭 | 保留根据任务生成依赖关系的动态规划 |
| 响应方式 | 前台完成后汇总 | 在原对话查看主 Agent 的最终交付 |

点击**保存**。配方还包含最大并发 2、每名成员 10 分钟超时、30,000 Token 软预算，以及最多
一轮返工的质量门。保留这些设置即可；软预算只限制后续调度，不是精确的总用量或费用上限。
配方的**失败处理**为回退重试；如需备用路由，在每个成员的**可靠性与预算**中配置成对的
回退提供方和模型。

在**成员库 → 工具权限**中核对任务需要的工具：实现成员需要读写当前演示项目并运行本地
测试，审核成员需要读取代码和执行检查。使用你实际安装的 DSH 工具名，不要照抄其他环境的
工具名。父对话也必须具备这些能力；给成员配置工具不会扩大父对话本来没有的权限。

## 4. 在空临时项目中发送任务

在 macOS/Linux 终端创建独立目录，记下输出路径：

```sh
TEAM_DEMO_DIR=$(mktemp -d "${TMPDIR:-/tmp}/dsh-team-demo.XXXXXX")
printf '%s\n' "$TEAM_DEMO_DIR"
```

Windows PowerShell 可使用：

```powershell
$teamDemoDir = Join-Path ([System.IO.Path]::GetTempPath()) ("dsh-team-demo-" + [guid]::NewGuid())
New-Item -ItemType Directory -Path $teamDemoDir
```

在 DSH 中将这个目录作为项目打开，并新建对话。确认对话工作目录是该临时目录。
打开普通输入框旁的**小队 / 单人 / 继承**控件，在**选择小队**中选中导入的小队，再选中
**本对话选择小队**。确认**仅下一条消息**为**跟随对话模式**，避免先前排队的单人选择覆盖首跑。

发送下面的完整任务：

```text
请在当前空临时项目中实现一个无外部依赖的待办清单。

范围：
- 只在当前项目写入 index.html、app.mjs、app.test.mjs、README.md。
- 不安装依赖，不访问外部服务，不提交 Git，不发布，不修改其他项目。
- 不需要持久化、登录或后端；CSS 可以直接写在 index.html 中。

验收标准：
- 新增任务时去掉首尾空白，拒绝空内容；显示清楚的输入错误和空列表提示。
- 可以完成/取消完成、删除任务；剩余计数始终等于未完成任务数。
- 输入框有可访问名称，操作使用原生按钮/复选框，键盘可以完成主要流程。
- app.mjs 中的状态逻辑可以在 Node 中导入，不依赖浏览器 DOM。
- 用 Node 自带测试运行器验证新增、拒绝空白、切换完成、删除和剩余计数。
- README.md 说明如何在本地打开页面、运行测试，以及人工检查步骤。

分工：规划成员先给验收标准和边界条件；实现成员据此实现并执行检查；
审核成员在实现完成后独立核对代码和实际测试输出，必要时明确指出返工项。
执行 node --test。最终汇总交付文件、实际执行的检查及其结果、未验证项和剩余问题。
不要把未执行的测试或浏览器检查写成通过。
```

动态规划的阶段数量和文字会随模型变化。角色成员与对话主模型不是同一个概念：主模型生成
分工并汇总，小队中的 Product planner 负责验收标准。配方还会在成员交付后调用质量门审核，
所以审核角色可能出现在成员执行和后续审核两个位置。

## 5. 检查产物和运行证据

| 检查位置 | 要核对的内容 |
| --- | --- |
| 临时项目目录 | `index.html`、`app.mjs`、`app.test.mjs`、`README.md` 是否存在，是否只修改约定目录 |
| 测试输出 | 实际执行 `node --test`；测试覆盖要求的行为，并且输出没有失败 |
| 浏览器页面 | 新增带首尾空白的任务；提交空白；完成再取消；删除；核对计数和空状态；用键盘走主要流程 |
| 最终对话回答 | 交付路径、实际检查结果、未验证项和剩余问题是否清楚 |

你也可以在该项目目录手动重跑 `node --test`。模块页面通常需要本地 HTTP 服务；按生成的
README 启动仅供本机访问的静态服务并检查页面，避免把 `file://` 下的模块限制当作功能错误。
如果模型没有浏览器工具，浏览器验收应明确留作人工检查。

在对话的**小队运行**视图展开对应记录，可查看**执行计划、依赖阶段、成员输出、审核与返工**。
输入区的运行状态也提供**查看运行**入口。运行中的任务可用**停止运行**取消；结束后可以
**重试整次运行**、**仅重试此成员**或**导出运行**。重试会产生新的关联记录。

同一视图中的**洞察**页签提供时间范围和按小队、模型、项目的汇总。Token 由 Provider 上报，
分为非缓存输入、缓存读取、缓存写入、输出，并区分规划器、成员、审核与返工。**部分计量**或
**Provider 未上报用量**不等于零；这里只展示用量，不会推测货币费用。

“交给主 Agent 汇总”表示小队交接已就绪，运行中心不追踪主 Agent 最终回答。绿色的完成状态
也不能代替文件检查或测试证据。以实际生成的文件、命令输出和可复现行为判断这次交付。

## 安装或首跑遇到问题

| 现象 | 处理方式 |
| --- | --- |
| `dsh: command not found` | 克隆源码不会自动创建全局命令。在 Harness 仓库运行 `pnpm dsh --version`；本文的 `dsh ...` 可替换为 `pnpm --dir /absolute/path/to/deepseek-harness dsh ...` |
| Node 版本不支持 | 使用 Node `>=22.19.0 <23` 或 `>=24.0.0`；不要使用 Node 23 |
| 安装后看不到“小队”或提示前后端版本不一致 | 确认安装到 `web` profile，重启 DSH 进程并刷新浏览器；记录插件版本 `1.1.0` 和实际 DSH 版本 |
| 发布包下载失败 | 从 [v1.1.1 Release](https://github.com/toolclub/dsh-agent-team-gui/releases/tag/v1.1.1) 下载 `.tgz`，然后运行 `dsh plugin --profile web add -w /absolute/path/to/dsh-agent-team-gui-1.1.1.tgz`；或使用下方固定 Git tag |
| 预览一直显示缺少路由 | 先在 DSH 配置可用模型，再映射每个缺失路由；导入后到“成员库”核对具体模型 |
| 确认导入不可用，或提示预览失效 | 完成所有映射，等待自动预览结束；定义在其他窗口变化后，重新点击“预览” |
| 发消息没有运行小队 | 检查“本对话选择小队”、正确的小队选择，以及“仅下一条消息”；首跑将使用方式改为“Host 强制派工”、派工策略改为“执行已派任务”、成员选择改为“全部成员”并保存 |
| 只返回代码文本，没有文件或检查 | 检查父对话的文件/命令工具以及成员“工具权限”，并确认项目工作目录；提示词无法补齐没有授权的工具 |
| 超时、质量门未通过或部分完成 | 展开具体成员和审核输出，先定位模型、工具或验收问题；必要时修复后重试，不要把失败当作成功 |
| Token 显示“—”或部分计量 | 查看 Provider 的计量覆盖；没有上报的用量不会被填为 0 |

可用下面的命令检查组合配置：

```sh
dsh --profile web --dump-config
```

预期能看到 `dsh-agent-team-gui` bundle 层和 `agent-team-gui` 行。

需要从 Git 安装时，固定到同一个版本：

```sh
dsh plugin --profile web add -w github:toolclub/dsh-agent-team-gui#v1.1.1
```

Git 安装需要执行 `prepare` 构建。pnpm 10 或更高版本可能提示构建授权；在它提示的 Web
profile `pnpm-workspace.yaml`（通常位于 `~/.dsh/profiles/web/`）中按下文说明配置 `allowBuilds`，保留其他
已有设置，然后重新运行同一条安装命令。源码应先审查，授权限于这个包：

复制 pnpm 错误中打印的**准确包键**到 `allowBuilds`；该键可能包含解析后的完整 revision。
只授权这一条，并保留文件中已有配置。

更多源码安装方式见 [README](../README-zh.md#其他安装方式)。仍然失败时，提交
[Issue](https://github.com/toolclub/dsh-agent-team-gui/issues/new/choose)，附上 OS、Node、pnpm、
DSH、插件版本、准确安装命令和脱敏后的错误。运行导出包含任务与成员输出，分享前先检查内容。

跑通后，在新对话再次选择同一个小队即可复用。欢迎分享你实际使用的配方和遇到的问题；如果
这个工作流对你有用，也欢迎给项目点一个 [Star](https://github.com/toolclub/dsh-agent-team-gui)。
